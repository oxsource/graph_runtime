# Implementation Plan: Profiler Framework

**Branch**: `010-profiler-framework` | **Date**: 2026-07-28 | **Spec**: [spec.md](./spec.md)

## Summary

Add a MediaPipe-inspired profiling mechanism to graph_runtime for measuring per-node execution performance. The profiler supports RAII Scope-based Open/Process/Close timing, configurable TimeHistograms, an abstract Clock interface for testability, a build-time stub switch for zero-overhead production builds, and a public API on `GraphRuntime` for querying `NodeProfile` results.

## Technical Context

**Language/Version**: C++17 (`-std=c++17` enforced by `.bazelrc`)

**Primary Dependencies**: 
- `com_google_absl//absl/time` — for `absl::Time` / `absl::Duration` conversions in Clock
- `com_google_absl//absl/status` — existing dependency, may be needed for profiler error handling
- No new external dependencies required

**Storage**: Profile data is serialized to JSON files on disk via `WriteProfile()`. JSON is chosen for human readability and for compatibility with the existing `nlohmann/json` dependency in the project. The Reporter reads these JSON files for offline analysis.

**Testing**: 
- `bazel test //...` with `googletest` (existing)
- New profiler unit tests under `src/tests/`
- Build-time switch tested via `--define graph_runtime_profiler=true` and default

**Target Platform**: macOS ARM64, Linux x86_64 (existing platform support)

**Project Type**: C++ library (graph runtime framework)

**Performance Goals**: 
- Profiler Scope overhead: <100ns per call when enabled at runtime
- TimeHistogram accumulation: 1M samples in <100ms (5 buckets, 1s intervals)
- Zero overhead when disabled (at build time or runtime)

**Constraints**:
- Must compile with existing `-fvisibility=hidden`, `-fvisibility-inlines-hidden`
- Public API symbols must use `GRAPH_RUNTIME_API` macro
- All include paths follow the `@graph_runtime//` prefix convention in BUILD deps
- Profiler module must live under `src/framework/profiler/` as an internal module

**Scale/Scope**: Phase 1 covers core profiler + JSON serialization (`WriteProfile`) + basic `Reporter` library + CLI `print_profile` tool. No trace events, no stream latency tracking, no periodic auto-write.

## Phases

### Phase 0 — Research & Technical Decisions

See [research.md](./research.md) for detailed findings. Key decisions:

1. **Clock**: `absl::Time`-based abstract interface with `RealClock` (wrapping `std::chrono::steady_clock`) — consistent with existing codebase's use of `absl::Time` in Logger
2. **Build Switch**: Single `config_setting` (`graph_runtime_profiler=true`) with `graph_runtime_select()` to choose real vs. stub — follows the MediaPipe pattern adapted for this project's platform conventions
3. **Thread Safety**: `std::mutex` on histogram updates + `std::atomic<bool>` for `is_profiling_` flag — sufficient for Phase 1; lock-free CircularBuffer deferred to Phase 2

```cpp
namespace graph::runtime {
```

#### 1.4 — GraphProfiler / GraphProfilerStub / ProfilingContext

Files: `src/framework/profiler/graph_profiler.h`, `src/framework/profiler/graph_profiler.cc`

The header conditionally exposes either `GraphProfiler` (real) or `GraphProfilerStub` (no-op) based on `GRAPH_RUNTIME_PROFILER_ENABLED`. `ProfilingContext` always inherits from whichever is active.

```cpp
// graph_profiler.h — simplified sketch

#ifdef GRAPH_RUNTIME_PROFILER_ENABLED

class GraphProfiler {
 public:
  enum class EventType { OPEN, PROCESS, CLOSE };

  class Scope {
   public:
    inline Scope(EventType type, const std::string& node_name,
                 GraphProfiler* profiler);
    inline ~Scope();
   private:
    EventType type_;
    std::string node_name_;
    GraphProfiler* profiler_;
    int64_t start_time_usec_ = 0;
  };

  void Initialize(const ProfilerConfig& config,
                  const std::vector<std::string>& node_names);
  void SetClock(std::shared_ptr<Clock> clock);
  void Start();
  void Stop();
  void Pause();
  void Resume();
  void Reset();

  struct NodeProfile {
    std::string node_name;
    int64_t open_runtime_usec = 0;
    int64_t close_runtime_usec = 0;
    TimeHistogram process_runtime;
  };
  std::vector<NodeProfile> GetNodeProfiles() const;
  const ProfilerConfig& profiler_config() const;

 private:
  int64_t TimeNowUsec();
  void SetOpenRuntime(const std::string& name,
                      int64_t start_usec, int64_t end_usec);
  void AddProcessSample(const std::string& name,
                        int64_t start_usec, int64_t end_usec);
  void SetCloseRuntime(const std::string& name,
                       int64_t start_usec, int64_t end_usec);

  ProfilerConfig config_;
  std::atomic<bool> is_profiling_{false};
  std::atomic<bool> is_initialized_{false};
  std::shared_ptr<Clock> clock_;
  mutable std::mutex mutex_;
  struct PerNodeData {
    std::atomic<int64_t> open_runtime_usec{0};
    std::atomic<int64_t> close_runtime_usec{0};
    TimeHistogram process_runtime;
  };
  std::map<std::string, PerNodeData> node_data_;
};

class ProfilingContext : public GraphProfiler {
  using GraphProfiler::GraphProfiler;
};

#else  // GRAPH_RUNTIME_PROFILER_ENABLED — stub

class GraphProfilerStub {
 public:
  enum class EventType { OPEN, PROCESS, CLOSE };
  class Scope {
   public:
    inline Scope(EventType, const std::string&, GraphProfilerStub*) {}
    inline ~Scope() {}
  };
  void Initialize(const ProfilerConfig&, const std::vector<std::string>&) {}
  void SetClock(std::shared_ptr<Clock>) {}
  void Start() {}
  void Stop() {}
  void Pause() {}
  void Resume() {}
  void Reset() {}
  struct NodeProfile {
    std::string node_name;
    int64_t open_runtime_usec = 0;
    int64_t close_runtime_usec = 0;
  };
  std::vector<NodeProfile> GetNodeProfiles() const { return {}; }
  const ProfilerConfig& profiler_config() const;
};

class ProfilingContext : public GraphProfilerStub {
  using GraphProfilerStub::GraphProfilerStub;
};

#endif  // GRAPH_RUNTIME_PROFILER_ENABLED
```

Key implementation details for `Scope`:
- Constructor reads `start_time_usec_ = profiler_->TimeNowUsec()` (atomic check `is_profiling_` first — if false, skip)
- Destructor dispatches to `SetOpenRuntime`, `AddProcessSample`, or `SetCloseRuntime` (again guarded by `is_profiling_`)
- The `inline` specifier allows the compiler to inline away the entire Scope when the stub is active

#### 1.6 — Integration Points

**GraphRuntime** changes:
- New member: `std::unique_ptr<ProfilingContext> profiler_`
- In `Initialize()`: create `ProfilingContext`, call `profiler_->Initialize(config_.profiler_config, node_names)`, set clock
- New public methods:
  - `ProfilingContext* profiler() { return profiler_.get(); }`
  - `void SetProfilerConfig(const ProfilerConfig& config)` — stores config; applied during subsequent `Initialize()`
  - `std::vector<NodeProfile> GetNodeProfiles() const` — delegates to `profiler_->GetNodeProfiles()`
- Pass `profiler_.get()` to `scheduler_->SetProfiler(profiler_.get())`

**Scheduler** changes:
- New member: `ProfilingContext* profiler_ = nullptr`
- New method: `void SetProfiler(ProfilingContext* p) { profiler_ = p; }`
- In `Schedule()` (sync path): wrap `node->Open(ctx)` with `Scope(Scope::OPEN, ...)` and `node->Close(ctx)` with `Scope(Scope::CLOSE, ...)`
- Pass `profiler_` to each `SchedulerQueue::SetProfiler(profiler_)`

**SchedulerQueue** changes:
- New member: `ProfilingContext* profiler_ = nullptr`
- New method: `void SetProfiler(ProfilingContext* p) { profiler_ = p; }`
- In `RunNode()`:
  - Open branch: `Scope scope(Scope::OPEN, node->name(), profiler_);`
  - Process branch: `Scope scope(Scope::PROCESS, node->name(), profiler_);`

#### 1.8 — Config Parser Updates

The `profiler_config` field lives on `GraphConfig`, so any `IGraphConfigParser` implementation (JSON, future YAML/Protobuf/DSL) can populate it. Each parser handles its own format's syntax for the same struct fields.

**JSON parser** (`json_parser.cc`): parse `profiler_config` block from the JSON root:

```json
{
  "profiler_config": {
    "enable_profiler": true,
    "histogram_interval_size_usec": 2000000,
    "num_histogram_intervals": 5,
    "trace_log_path": "/var/log/graph_profiles"
  },
  "nodes": [...]
}
```

All fields are optional; defaults come from `ProfilerConfig` struct defaults. When a future YAML or Protobuf parser is added, it fills the same `GraphConfig::profiler_config` fields — no runtime changes needed.

#### 1.9 — Profile JSON Serialization (WriteProfile)

Files: `src/framework/profiler/profile_writer.h`, `src/framework/profiler/profile_writer.cc`

The `WriteProfile()` method on `GraphProfiler` (real) serializes all accumulated `NodeProfile` data to a JSON file. When `path` is empty and `trace_log_path` is set in `ProfilerConfig`, the file is written to `<trace_log_path>/profile_<graph_name>_<timestamp>.json`. When `path` is provided explicitly, it takes precedence.

```cpp

// On GraphProfiler:
absl::Status GraphProfiler::WriteProfile(const std::string& path = "");

}
```

Output JSON format:
```json
{
  "capture_time": "2026-07-28T12:00:00.000Z",
  "node_count": 2,
  "profiler_config": {
    "enable_profiler": true,
    "histogram_interval_size_usec": 1000000,
    "num_histogram_intervals": 5,
    "trace_log_path": "/tmp/profiles"
  },
  "nodes": [
    {
      "node_name": "source",
      "open_runtime_usec": 42,
      "close_runtime_usec": 0,
      "process_count": 100,
      "process_time_total_usec": 123456,
      "process_time_mean_usec": 1234.56,
```

#### 1.10 — Reporter Library

Files: `src/framework/profiler/reporter/reporter.h`, `src/framework/profiler/reporter/reporter.cc`

The `Reporter` class reads profile JSON files and computes aggregate, comparable statistics:

```cpp
namespace graph::runtime {

struct ProfileReport {
  struct NodeStats {
    std::string node_name;
    int64_t open_runtime_usec;
    int64_t close_runtime_usec;
    int64_t process_count;
    int64_t process_time_total_usec;
    double process_time_mean_usec;
    int64_t process_time_min_usec;
    int64_t process_time_max_usec;
  };

  std::vector<NodeStats> nodes;
  int64_t total_process_count = 0;
  int64_t total_process_time_usec = 0;
};

class Reporter {
 public:
  // Load one or more profile files. When multiple files are loaded,
  // per-node statistics are aggregated (sum counts, sum totals, recompute means).
  absl::Status Accumulate(const std::string& json_path);

  // Generate a formatted report.
  ProfileReport Report() const;

  // Compare this report with a baseline report; returns delta entries.
  struct Delta {
    std::string node_name;
    double process_mean_delta_usec;  // positive = slower
    double process_mean_delta_pct;
  };
  std::vector<Delta> Compare(const ProfileReport& baseline) const;

  // Clear all accumulated data.
  void Clear();
};

}  // namespace graph::runtime
```

Formatting is handled by the caller (CLI tool), keeping the `Reporter` focused on data aggregation.

#### 1.11 — CLI Tool (print_profile)

File: `src/framework/profiler/reporter/tools/print_profile.cc`
