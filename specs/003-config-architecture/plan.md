# Implementation Plan: Configuration Architecture — IGraphConfigParser & JSON Parser

**Branch**: `003-config-architecture` | **Date**: 2026-07-23 | **Spec**: `/specs/003-config-architecture/spec.md`

**Input**: Feature specification from `/specs/003-config-architecture/spec.md`

**Note**: This plan focuses on the config parsing abstraction layer (IGraphConfigParser) and its JSON default implementation, following the architecture defined in `project_bootstrap.md §3.4`.

## Summary

Design and implement the configuration parsing layer for Graph Runtime. Deliverables include: `IGraphConfigParser` abstract interface, `JsonParser` default implementation using nlohmann/json, `ConfigValidator` for shared validation logic, and `ParserRegistry` for format auto-detection. The parsing layer sits between config files (JSON) and `GraphBuilder::Build()`, keeping Runtime fully decoupled from config format.

## Technical Context

**Language/Version**: C++17 (inherited)

**Primary Dependencies**: nlohmann/json (header-only, already in graph_runtime_deps.bzl), absl::Status/StatusOr (inherited)

**Storage**: N/A — config files read from local filesystem, parsed into in-memory GraphConfig

**Testing**: GoogleTest via Bazel cc_test — unit tests per parser + ConfigValidator integration test

**Target Platform**: macOS ARM64 (development), Linux x86_64 (deployment)

**Project Type**: C++ library extension — new module under `graph_runtime/src/config/`

**Performance Goals**: Parse a 50-node JSON config in under 100ms

**Constraints**:
- Runtime MUST NOT import any JSON/YAML headers — config format must be fully decoupled
- `IGraphConfigParser::Parse()` returns `absl::StatusOr<GraphConfig>` — never throws
- nlogmann/json must be accessed only within `src/config/json/` — no other module may include it
- GraphConfig structure already exists in `graph_runtime/src/config/graph_config.h`

**Scale/Scope**: Phase 1: JSON only; interface designed for YAML/Protobuf in Phase 2

**Structure Decision**: Two Bazel cc_library targets in the config module:
- `//src/config:config` — interface + validator + registry. Has zero external deps beyond absl.
- `//src/config/json:json` — JsonParser implementation. Depends on nlohmann/json.
- External code depends only on `//src/config:config`; never on `//src/config/json` directly.
- `GraphRuntime::Initialize(config_file)` uses `ParserRegistry` to auto-detect format and dispatch to the correct parser.

## Architecture Overview

```
                           ┌──────────────────────┐
Config file (pipeline.json)│   JsonParser          │
                           │   (uses nlohmann/json)│
                           └──────────┬────────────┘
                                      │
                           ┌──────────▼────────────┐
                           │  IGraphConfigParser   │
                           │  (abstract interface) │
                           └──────────┬────────────┘
                                      │ Parse(file) → StatusOr<GraphConfig>
                           ┌──────────▼────────────┐
                           │  ConfigValidator       │
                           │  (shared validation)   │
                           └──────────┬────────────┘
                                      │
                           ┌──────────▼────────────┐
                           │  GraphConfig           │
                           │  (immutable, format-   │
                           │   agnostic)            │
                           └──────────┬────────────┘
                                      │
                           ┌──────────▼────────────┐
                           │  GraphBuilder::Build() │
                           │  (validates, creates)  │
                           └───────────────────────┘
```

**Abstraction boundary**: `IGraphConfigParser` is the sole boundary between config format (JSON/YAML/etc.) and the runtime. `GraphBuilder` receives a `GraphConfig` and never knows what format it came from. `ConfigValidator` is shared between parsers (during parse) and GraphBuilder (during build) to ensure consistent validation.
